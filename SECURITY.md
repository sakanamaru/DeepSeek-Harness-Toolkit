# Security Policy

DeepSeek Harness Toolkit is an **unofficial** Windows toolbox for DeepSeek Harness (dsh).
It handles your dsh data directory (typically `~/.dsh`), files stored inside it, and can
delete data — so treat it as a data-management tool, not just a launcher.

The project is developed in the open ([MIT](LICENSE)); the trust model is **verifiable
mechanisms, not promises**: every release is built from source by GitHub Actions, ships a
CI-generated `hashes.txt` (SHA-256), and the manifest is GPG-signed by the maintainer
(see [Verifiability](#verifiability)).

## Reporting a Vulnerability

If you discover a security issue — especially anything involving:

- data deletion / wipe behavior,
- backup / restore / import path handling,
- or exposure of credentials stored inside the dsh data directory,

please **report it privately** instead of opening a public issue:

- Use GitHub's private report flow: https://github.com/sakanamaru/DeepSeek-Harness-Toolkit/security/advisories/new
- Or contact the maintainer: https://github.com/sakanamaru

Please include:

1. A short description of the issue.
2. The release tag / commit you tested.
3. Steps to reproduce (paths, OS version, what ran).
4. Any relevant output or proof-of-concept.

## Scope

| In scope | Out of scope |
|---|---|
| This repository's latest release tag | **DeepSeek Harness itself** (https://github.com/deepseek-ai/dsh) |
| The toolkit's own source (`dsh_v2.cs`) and CI pipeline | Node.js / npm / third-party packages |
| Backup / restore / wipe data handling | |

## Permission boundary (what the program may touch)

The toolkit **never asks for administrator rights** (no UAC elevation, no manifest
`requireAdministrator`). It runs as the current standard user and:

| Does | Does NOT |
|---|---|
| Read/write a small state area next to the exe (`launcher.config`, `backups\`, `logs\`) | Write registry `Run` keys, install Windows services, or touch system files |
| Read your dsh data directory when backing up / restoring / wiping (see below) | Access your browser, clipboard, credential store, or other users' data |
| Run `npm install` (with your approval) to install/update dsh | Exfiltrate anything: the program makes no outbound calls beyond the endpoints listed below |

If you see it request administrator elevation or attempt writes outside these areas,
that is a bug — please report it.

## Network endpoints (complete list)

The toolkit only ever connects to these hosts. **Any new endpoint requires a changelog
entry in the release notes** — if you see a connection elsewhere, report it:

| Endpoint | Purpose |
|---|---|
| `registry.npmjs.org` | Installing / updating dsh (default official npm registry) |
| `registry.npmmirror.com` | Optional China mirror for installs (`L` picker) |
| `api.github.com` / `github.com` | Version check (new release lookup); opening the GitHub page when you press `G` |
| `127.0.0.1:3080` | Your local dsh web service (health probe, status monitoring) |

There is **no telemetry, no analytics, no crash reporting**, and no connection except
the ones above and what the npm client itself does for installs.

## Data-safety notes

- The toolkit **never deletes your dsh data without explicit interaction**: wipe requires a
  two-step confirmation (today's date + `yes`), the dsh web service must be stopped, and an
  automatic pre-backup is made before wiping, restoring or importing.
- `stop` refuses to kill a process that is not confirmed to be dsh (a foreign program
  holding `127.0.0.1:3080` is never killed — the command fails with an explanation).
- Manual backups (no suffix) are kept forever; only auto/protection backups
  (`-auto`, `-pre-*`) are cleaned by the retention policy.
- Backups are plain files/directories — keep them somewhere you trust.
- This is an unofficial project and is **not affiliated with DeepSeek**.
- `selftest` CLI (or GUI 体检 report) is strictly read-only: it only inspects and prints.

## Verifiability

Every release is built from source by GitHub Actions (see
[build-release.yml](.github/workflows/build-release.yml)); the source == artifact claim
can be checked by building `dsh_v2.cs` yourself with `csc` (see
[Build from Source](README.md)).

- **`hashes.txt`** in each release lists SHA-256 of every artifact; it is generated by CI
  from the same files it built.
- **GPG signature**: `hashes.txt.asc` is a detached signature by the maintainer:
  - Public key: [`keys/sakanamaru-gpg.asc`](keys/sakanamaru-gpg.asc)
  - Fingerprint: `A2F67D170B5BE4845612642C240979232B4E4CE4`
  - Verify with `gpg --verify hashes.txt.asc hashes.txt` (import the key first).
- **`verify.ps1`** automates the whole check (download → SHA-256 → GPG → provenance links):

  ```powershell
  powershell -ExecutionPolicy Bypass -File verify.ps1 -OutDir D:\verify
  ```

  Run it before using a download. It is read-only and installs nothing.

Note on reproducibility: the project targets the classic .NET Framework `csc.exe`
(no `/deterministic`); binaries differ byte-wise between builds (module MVID), so
byte-identical reproduction is **not** promised — functional equivalence is verified by
the CI test suite (unit + integration) that runs on every push.
